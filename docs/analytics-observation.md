## 事件口径

| 事件 | 触发时机与用途 |
| --- | --- |
| `tool_cta_clicked` | 首页/场景页 SmartCTA 点击，区分选图、打开工作台、继续历史任务 |
| `upload_picker_opened` | 共享选图区域点击；仅表示尝试打开选择器，取消选择不会产生 upload_started |
| `upload_started` / `upload_succeeded` / `upload_failed` | 选定文件后开始校验、图片解码完成或失败；upload 指本地读取，不是上传图片到服务器 |
| `processing_started` / `processing_succeeded` / `processing_failed` / `processing_canceled` | 分割、九宫格、轮播、压缩、去背景的实际处理；去背景逐张记录，其他批处理按一次操作记录 |
| `processing_blocked` | 缺少分割线、分割线未经过图片、去背景模型不可用，处理尚未开始 |
| `export_started` / `export_succeeded` / `export_failed` / `export_canceled` | 全部十种核心工具的导出操作；单图、选中项、批量打包分别记录，适用时记录输出数量和格式 |
| `download_triggered` / `download_failed` | 浏览器下载点击已触发或同步失败，不证明操作系统已保存文件 |
| `save_preview_opened` | iOS 保存流程打开图片预览，不等于用户已长按保存 |
| `results_readjusted` / `image_replaced` | 九宫格和轮播工作台的结果重调及更换图片 |

公共属性：`schema_version=1`、`page_path`、`locale`、`tool`。按操作补充 `input_count`、`output_count`、`failure_count`、`format`、`action`、`duration_ms`、`error_code`。耗时属于一次本地操作，不是服务器响应时间。

自定义属性不包含文件名、图片、图片内容、对象 URL、文本水印内容、用户标识或原始异常。自定义事件 URL 使用 pathname，不包含查询参数和 hash。现有 Umami 页面访问仍保留正常来源归因。

默认仅允许 imgsplit.com 和 www.imgsplit.com；localhost 和 Vercel 预览域名不采集。脚本未就绪时最多暂存 50 个事件，队列仅驻留内存。脚本加载后发送，保留操作开始时的页面；统计服务异常不会阻断图片操作。浏览器屏蔽脚本、断网或页面过早关闭时可能丢事件。

调整尺寸、水印、打码、拼图、社媒导出是即时编辑流程，使用“选图成功 → 导出成功”分析，不强行要求中间 processing 事件。去背景的逐图事件量也不能直接与其他工具的批量操作次数比较。

## 3–5 天后如何复盘

1. 从部署完成后的完整自然日开始，先确认事件和性能样本持续增长；排除部署当晚的人工验收。
2. 按 **工具 × 设备 × 入口页面 × 来源** 比较：有选图成功的访问数 / 落地访问数、有导出成功的访问数 / 有选图成功的访问数。使用同一时间窗内的访问或会话去重，不用事件次数冒充用户转化率。
3. 检查 `upload_failed`、`processing_blocked`、`processing_failed`、`export_failed` 的错误码分布；分析失败次数时明确重试可能重复计数。
4. 优先查看 Bing、Doubao 和 `/zh-CN/split-in-half`、长截图入口，确认用户是否真正完成本地处理。
5. 性能按页面和设备查看 LCP、INP、CLS 及样本量；没有样本不能解释为 0 ms 或“优秀”。
6. 样本少的渠道继续观察到 7–14 天。先处理明确错误和明显流失，再决定是否调整首页上传入口或增加场景预设。

新增事件、hash 合并和真实用户结构都会影响仪表盘数值。不要把上线前后原始 PV、跳出率的变化直接归因于体验改善；旧数据没有操作事件，无法追溯计算旧的导出转化率。

## 首轮复盘后的优化（2026-10-19，本地验证，尚未部署）

### 体验与 ZIP 排查

- 分割线未穿过图片时，持续展示放线指引并禁用“生成”；单图提供上下/左右等分线，多图按当前选中图片的中心放线。线位置取整后必须严格位于图片内部，防止边界线生成未切割图片。
- 第一版为所有六种语言补充大图处理提示和重新选图入口；随后按用户要求取消 20 MB 固定上限，以下“大图准入检查”取代第一版的文件体积判断。
- 分割工具 ZIP 导出加互斥锁和打包状态；所有/选中/单张下载的异常由界面接住，结果和选择保留，允许重试或逐张保存。浏览器下载使用挂载到 DOM 的临时链接，成功点击后延迟 1 秒释放 Blob URL，失败立即清理。
- 共享 ZIP 实现区分 `zip_load_failed`、`zip_read_failed`、`zip_generate_failed`，触发下载异常为 `download_failed`；未知异常保留 `export_failed`。分析仅发送错误码，不发送原始异常或文件名。
- 旧的 8 次 ZIP 失败集中在同一会话，不能当成 8 个失败用户。已修复代码中可确认的无忙碌状态、未处理 Promise 拒绝和立即回收下载 URL 的问题；旧数据不足以证明那次失败究竟由模块加载、读图或打包引起。

### 事件 schema 2

| 属性 | 语义 |
| --- | --- |
| `occurred_at_ms` | 事件发生时的客户端毫秒时间，入队时记录，补发时不重写 |
| `event_sequence` | 同一页面实例内单调递增的事件序号；丢事件可能产生空档 |
| `page_instance_id` | 内存中的随机页面实例号，SPA 路由切换保持，整页刷新重建，不是用户/会话 ID |
| `operation_id` | 每次 upload / processing / export 的随机编号，开始与唯一终态共享 |
| `operation_started_at_ms` | 该次操作的原始开始时间 |

`schema_version` 更新为 2，其余已有属性继续保留。队列最多等待 50 个事件，按顺序发出；单个统计请求超过 5 秒即释放队列，不阻塞图片操作，不自动重试以免重复计数。超时并不取消已发出的请求，因此到达顺序仍不是最终依据。

复盘时先按 `page_instance_id + event_sequence` 还原页面内顺序，按 `operation_id` 配对开始与终态，结合 `occurred_at_ms` 和 `duration_ms` 检查耗时。不能把页面实例数、操作数当成独立用户或 Umami 会话数；跨页面、时钟调整、缺失终态仍需单独处理。

保留 Umami 默认服务端事件时间和会话行为，不覆盖顶层 `timestamp`。Umami 的[时间覆盖接口](https://docs.umami.is/docs/tracker-functions)只使用秒级 Unix 时间，[上游接收端](https://github.com/umami-software/umami/blob/master/src/app/api/send/route.ts)在带 timestamp 时的访问过期逻辑也不同；客户端毫秒时间放在事件属性中用于审计。因此仪表盘原生漏斗和时间轴仍可能受集中补发影响，本改动不会修复历史事件，也不承诺原生漏斗已具备毫秒排序。

“生成”被禁用后，常规点击不再产生 `no_split_lines` 阻塞事件，其数量下降不能独立证明转化改善；应继续比较选图成功到导出成功的会话转化和实际导出失败率。导出成功仍只表示打包完成且浏览器下载已触发，不证明操作系统保存完成。

## 大图准入检查（2026-10-19，本地，尚未部署）

### 判断方式

- 删除共享上传入口的单文件 20 MiB 拒绝与总文件 50 MiB 警告。首页、pSEO、工具页及全部六种语言的相关说明同步更新；大文件不再仅因超过 20 MB 被拒绝。
- 在创建图片对象 URL、解码像素之前，从 PNG / JPEG / WebP 文件头读取宽高。只读取小切片，跳过压缩数据；元数据扫描最多 2048 次，无法可靠读取尺寸时拒绝并提示重新保存图片。APNG 与动画 WebP 计入帧数。
- 静态图片预计占用 = `宽 × 高 × 4 × 3 + 文件字节数 × 2`；动画图片将像素副本数改为 `2 + 帧数`。这是为源像素、处理/输出缓冲及编码数据副本预留的参考值，不是浏览器实测内存。
- 设备提供 `navigator.deviceMemory` 时，预算为每 GiB 设备内存分配 64 MiB、最低 64 MiB、最高 512 MiB。无法读取时，粗指针设备使用 256 MiB，其他设备 512 MiB。达到预算 60% 时允许加载并提示可能较慢；超过预算则提示缩小像素尺寸或移除已加载图片。
- 批量选择先检查总预算，再逐张解码；追加图片计入编辑器已保留图片；同时解码的选择共用临时预算，解码失败后释放。解码后核对实际像素不超过文件头声明，避免直接继续处理异常尺寸。
- 单边超过 65,535 像素单独拒绝。压缩、水印、打码、去背景需要完整原图画布，继续采用项目已有的画布范围：面积 16,777,216 像素、单边 16,384 像素；分割等不必创建完整原图画布的工具使用内存预算。上述上限是保守产品策略，不代表所有浏览器的硬件极限。
- 调整尺寸与分割历史恢复使用相同准入检查。历史保存直接保留原文件，避免额外创建完整原图画布；九宫格/轮播重新选图时释放旧图片引用与对象 URL。
- 新增失败分类 `imageMemoryRisk`、`imageCanvasRisk`、`imageDimensionsTooLarge`、`imageMetadataUnreadable`；只发送分类，不发送文件名、图像内容、设备内存值或原始异常。历史恢复不产生新的 upload 事件。

浏览器的设备内存值是经过取整和限制的粗略信息，并非实时可用内存（[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/deviceMemory)）。其他标签页、浏览器内部副本、GPU 缓冲和去背景模型仍会影响峰值，因此预检不能保证所有设备绝不卡顿。文件头解析参照 [PNG IHDR](https://www.w3.org/TR/PNG-Chunks)、[WebP RIFF 格式](https://developers.google.com/speed/webp/docs/riff_container)及 [libjpeg-turbo SOF 解析](https://github.com/libjpeg-turbo/libjpeg-turbo/blob/main/src/jdmarker.c)。
